# Document Probe

> Read the shared document the way a CFO reads a P&L — with a specific question, not a highlighter. (~5 minutes)

## research_mode
File Analysis Plugin | Extracting what a prospect document reveals and what it deliberately hides

## context

The VP shared a deck with your account team two weeks ago. Most account teams read it once and move on. This phase treats that document as evidence. Upload it and interrogate it: what is it trying to get you to believe? What does it leave out? What operational priority is implied but never stated? The document was written by someone with an agenda. Find the agenda.

## tools_this_phase
File Analysis (Claude plugin) — upload the shared prospect document before starting.

## do_this

1. Upload the prospect document provided to this group. Ask Claude: "What is this document trying to get me to do or believe? What does it leave out that a competitor would ask about?"
2. Find one claim in the document that is not supported by the data shown. What would you need to verify it?
3. Find one operational priority that is implied by the document but never stated explicitly.
4. Write one question for the meeting that you would not have thought to ask without reading the document this way. Tag it [DOC].

## prompting_guideline

Do not ask Claude to summarise the document — you can read it yourself. Interrogate it instead. Use File Analysis and try: "Acting as a sceptical head of procurement who has seen a lot of vendor decks: what are the three things this document does not want me to notice? What question would immediately expose the weakest claim?" Then use those answers to build sharper questions for the meeting.

## checkpoint

Does your team have at least one meeting question you would not have asked without probing the document this way? If the document only confirmed what you already thought, you read it too passively. Try the sceptic prompt above.
